# Laconian

Laconian просит дать самый короткий законченный ответ, а не просто самый короткий ответ.

## Статус

Laconian — публичный философский проект и открытый бенчмарк в активной разработке. Сейчас
репозиторий содержит сквозной минимальный каркас: один переносимый навык, двуязычные
smoke-тесты, четыре варианта сравнения, офлайн-воспроизведение, детерминированную оценку,
необязательные слепые семантические суждения и имитируемый контракт одного адаптера реального
провайдера.

Публичных результатов бенчмарка пока нет. Фикстуры smoke-тестов проверяют архитектуру; они не
показывают, что `if` побеждает, экономит определённую величину или работает лучше другого
варианта.

## Почему «if»?

Плутарх, писавший несколько веков спустя, сохранил в трактате *О болтливости* 17
(*Моралии* 511A) анекдот о письменном обмене с Филиппом II. Филипп пишет угрозу, связанную со
вступлением в Лаконию; лакедемоняне письменно отвечают одним дорийским словом: `αἴκα` — «если». Само письмо
не сохранилось. До нас дошёл более поздний литературный рассказ Плутарха, а не современный
событиям документ.

Эта история служит образом проекта, а не доказательством гипотезы бенчмарка. Это также не
история о так и не состоявшемся вступлении: у Полибия 9.33 оратор признаёт, что Филипп вошёл
в Лаконию с войском.

## Что делает навык

[`skills/if/SKILL.md`](skills/if/SKILL.md) просит агента сначала определить законченный ответ,
а затем удалить только то, что можно убрать, не ослабляя правильность, безопасность,
соблюдение требований, существенные факты, выражение неопределённости, практическую
достаточность, ясность, тон или естественность языка.

Он удаляет приветствия, пересказ запроса, не запрошенное описание процесса, повторы и
украшения раньше, чем содержание. Он сохраняет запрошенные подробности, а также точные код,
команды, ошибки, числа, версии, URL, идентификаторы, цитаты и машиночитаемые структуры, когда
важна их точная форма.

Навык состоит из одного файла только в формате Markdown. В нём нет скриптов, зависимостей,
разрешений, справочных материалов, ресурсов, сетевых вызовов или инструкций для инструментов
конкретной платформы.

## Чего навык не делает

`if` не превращает речь в примитивный язык, не подменяет доказательства уверенностью, не
скрывает существенные оговорки, не сокращает вызовы инструментов, не минифицирует код, не
сжимает входной контекст и не выполняет действия. Он не отменяет просьбу о подробном учебном
руководстве, фиксированной структуре, доказательствах, примерах или заданной длине. Он не
обещает, что каждый агент или модель ответит одинаково.

## Установка и удаление

Скопируйте единственный файл навыка в каталог `if` среды агента, поддерживающей навыки в
формате Markdown:

```bash
mkdir -p "<agent-skills-directory>/if"
cp skills/if/SKILL.md "<agent-skills-directory>/if/SKILL.md"
```

Чтобы удалить навык, удалите скопированный файл:

```bash
rm "<agent-skills-directory>/if/SKILL.md"
rmdir "<agent-skills-directory>/if"
```

Подстановка зависит от среды. Минимальный каркас пока не заявляет поддержку установки во
всех перечисленных средах агентов.

## Бенчмарк с четырьмя вариантами

Каждый тестовый случай ответа сравнивается при одной и той же модели, пользовательском
запросе, настройках генерации, доступности инструментов и расположении инструкции. Меняется
только инструкция варианта:

| Вариант | Добавленная инструкция |
|---|---|
| `baseline` | Нет |
| `concise` | В точности `Answer concisely.` |
| `caveman` | Закреплённый по байтам автономный снимок полного навыка Caveman |
| `if` | Точные байты файла `skills/if/SKILL.md` из этого репозитория |

Основная гипотеза сравнивает `if` с `concise`. Варианты `baseline` и `caveman` дают контекст;
они не являются более простыми заменами основного сравнения. Активация и качество ответа
оцениваются отдельно.

## Порог качества и публикуемые метрики

Детерминированные ограничения проверяются до краткости. Затем необязательное семантическое
суждение может оценить обязательные факты и существенные предупреждения, не получая названия
варианта. Неудачный ответ не может победить лишь потому, что он короткий; парные разности
включают только совпадающие пары случая и повтора, в которых оба ответа проходят выбранный
порог качества.

В отчётах раздельно учитываются успешность по жёстким и семантическим критериям, нарушения
точных значений и формата, ошибки провайдера, повторы запросов, выходные токены или символы,
данные о задержке в сырых артефактах и парная разность между `if` и `concise`. Сводного балла
нет. Стоимость оценивается только по явно заданному датированному снимку цен и при достаточно
полном учёте провайдером токенов и кэша. См. полную [методологию бенчмарка](benchmarks/methodology.md).

## Быстрый старт

Офлайн-воспроизведение не требует доступа к сети или учётных данных провайдера:

```bash
uv sync --all-extras
uv run laconian validate evals/cases/response-smoke.yaml
uv run laconian validate evals/cases/activation-smoke.yaml
uv run laconian validate evals/manifests/replay-smoke.yaml
uv run laconian run evals/manifests/replay-smoke.yaml --results-root benchmarks/results
```

Последняя команда выводит уникальный каталог запуска. Скопируйте этот путь в `RUN_DIR`, затем
выполните оценку и сформируйте отчёт:

```bash
RUN_DIR="benchmarks/results/PASTE_THE_PRINTED_DIRECTORY_NAME"
uv run laconian score "$RUN_DIR/raw.jsonl" --cases evals/cases/response-smoke.yaml --output "$RUN_DIR/scored"
uv run laconian report "$RUN_DIR/scored/scored.jsonl" --output "$RUN_DIR/report.md"
```

Эти результаты офлайн-воспроизведения — локальные артефакты проверки, а не опубликованные
доказательства бенчмарка.

### Необязательный запуск с реальным провайдером

```bash
export OPENAI_API_KEY="your key"
uv sync --extra openai
uv run laconian run evals/manifests/openai-example.yaml --results-root benchmarks/results
```

Эта команда влечёт расходы у провайдера. Доступность модели может зависеть от учётной записи
и даты. Ключи API должны находиться только в настроенной переменной окружения; никогда не
помещайте их в манифесты или зафиксированные в репозитории файлы результатов. Результат запуска
с реальным провайдером не готов к публикации, пока не проверены идентификатор модели, сырые
артефакты, метод и ограничения.

## Структура репозитория

| Путь | Назначение |
|---|---|
| `skills/if/SKILL.md` | Весь переносимый навык |
| `src/laconian_eval/` | Независимые от провайдера исполнитель, оценка, граница суждений и отчётность |
| `evals/cases/` | Парные англо- и русскоязычные входные данные для ответов и активации |
| `evals/manifests/` | Воспроизводимая конфигурация запуска |
| `evals/baselines/caveman/` | Закреплённая сторонняя фикстура бенчмарка и атрибуция |
| `tests/fixtures/` | Синтетические данные офлайн-воспроизведения и судьи для автономных тестов |
| `benchmarks/methodology.md` | Правила публикуемого сравнения |
| `benchmarks/results/` | Будущие неизменяемые публичные артефакты запусков |
| `docs/` | Материалы о дизайне, философии и добавлении тестовых случаев |

## Участие в проекте

Начните с [CONTRIBUTING.md](CONTRIBUTING.md). Новые случаи должны опираться на доказательства,
быть нейтральными по отношению к вариантам и иметь пары на английском и русском языках.
Утверждения о бенчмарке требуют соответствующих сырых артефактов. Отчёты, затрагивающие
безопасность, направляйте согласно [SECURITY.md](SECURITY.md), а не в публичную задачу.
