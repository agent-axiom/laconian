# Laconian v0.1 Generation Capsule Slice 3 Execution Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add strict event history, read-only lifecycle verification, two-ledger crash recovery, and captured-input-only resume without ever repeating a provider call whose delivery is unknown.

**Architecture:** Keep immutable capsule verification and mutable recovery as separate boundaries. `events.py` owns strict event rows and identities; `history.py` consumes already parsed committed records and derives cross-ledger truth without mutation; `journal.py` owns descriptor-relative snapshots and append/fsync; `recovery.py` computes a complete pure recovery plan and authorizes mutation only by recomputing it internally; `execution.py` holds the exclusive lock, validates producer/runtime identity before credential access, reconstructs requests only from captured bytes, and durably records each start before calling a provider.

**Tech Stack:** Python 3.11+, Pydantic 2, POSIX descriptor APIs, `fcntl` locks through the existing filesystem adapter, pytest subprocess/multiprocessing handshakes, Ruff, mypy, and the Slice 1–2 canonicalization, provenance, import-policy, provider, sanitizer, and `RawAttemptV2` layers.

- Slice 2 prerequisite: commit `14b09ca` (`feat: define capsule attempt evidence`).
- `verify` is strictly read-only with respect to the capsule, its parent namespace, and every evidence byte. It may classify committed evidence but never truncate a tail, append a marker, or normalize history. For exact bounded validation only, it may use verifier-owned anonymous external scratch under the contract below; that scratch is not a capsule mutation capability.
- A held exclusive capsule lock returns canonical `status=busy`, null state, and no artifact inspection.
- An unmatched durable `request_started` is `AMBIGUOUS_INFLIGHT`; it is never retried and never receives a fabricated raw result.
- A durable raw row without its finish receives only a recovered finish. Missing auth, ambiguity, and completion markers are appended only when their meaning is already derivable.
- A nonempty bounded EOF suffix is torn even when it contains otherwise valid JSON without the required LF. A malformed newline-terminated row is committed corruption.
- Recovery validates both original ledger snapshots as one transaction before any mutation, then rechecks both exact identities, sizes, and hashes immediately before the first truncation.
- The approved design resolves a roadmap shorthand: provider construction occurs after `execution_started` but before `request_started`; construction failure commits `execution_blocked`. `request_started` is nevertheless appended and fsynced before the first possible `provider.generate()` call.
- Every task follows focused RED, observed expected failure, minimal GREEN, regression gates, two independent reviews, fixes, then one commit.
- No test reads a real credential, constructs a live network transport, sleeps to coordinate processes, or calls the network.
- Public `run` remains on the legacy v1 path through Task 14; Task 17 performs the cutover.

`resume_capsule` reports a preflight/runtime mismatch as the unchanged valid lifecycle projection, with the ordered deduplicated warning `producer_runtime_differs`; it does not manufacture an `invalid` status. The CLI maps that warning to exit 2 while preserving every capsule byte. This applies to dependency, adapter, transport, SDK, import-policy, package, or blocking runtime drift even when the runner package version itself still matches.

`HistoryContextV1` is defined in `history.py` as a frozen/slotted, class-bound-revalidated projection of exactly `CapsuleV1`, `ResolvedManifestV2`, `EnvironmentV1`, and the materialized `tuple[PlanRowV1, ...]`; it never accepts forged model state. `RecoveryContextV1` adds the compact history commitments from the descriptor-verified pair; `RecoveryPlanV1` contains exact truncations, append rows, post-state, and capacity. The pure planner accepts explicit operation/time only for reproducible calculation. `_MutatorSessionV1` additionally owns the same root/parent identities, exclusive lock, successful probe evidence, `JournalTransaction`, descriptor-bound verified context, and the one invocation operation ID. `RecoveryError` stores only a stable code and always renders `capsule recovery rejected`.

`ProviderFactoryRequest` is frozen/slotted and contains `provider_kind`, requested model, `api_key_env: str | None`, timeout, adapter digest, transport policy, SDK pair, and `captured_replay_bytes: bytes | None` (`repr=False`). Its kind matrix is exact: fake has both optional inputs null, `transport_policy="offline"`, and null SDK pair; replay has only captured replay bytes with the same offline/null-SDK fields; OpenAI has only a nonblank API-key variable plus `transport_policy="openai-direct-v1"`, `sdk_distribution="openai"`, and a nonnull SDK version. `ProviderBinding` contains the exact kind/adapter digest, repository provider (`repr=False`), and credential values (`repr=False`): each present value is nonempty, the tuple is empty exactly for fake/replay and has exactly one value for OpenAI. `ResumeError` stores only a stable code and always renders `capsule resume rejected`.

All new public validation/mutation errors use stable codes and constant messages. They never echo a path, secret, provider payload, forged model state, or torn-tail bytes.
