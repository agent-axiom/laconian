# Laconian v0.1 Generation Capsule Master Implementation Roadmap

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this roadmap through its linked slice execution plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build PR 3 as a self-contained, crash-safe generation capsule that binds every provider call to captured inputs, deterministic intent, exact producer provenance, append-only evidence, and an atomically verifiable seal without adding statistical or benchmark-outcome claims.

**Architecture:** Preserve the existing v1 manifest, runner, scoring, and reporting path until the explicit Slice 4 cutover. Add a separate `laconian_eval.capsule` package for canonical encoding, strict v2 schemas, bounded capture, provenance, POSIX durability, deterministic planning, journaling, execution, verification, and sealing. Treat provider bytes and authored inputs as untrusted opaque evidence; permit calls only after a prepared capsule is durably published and verified. Keep scoring/reporting as immutable sidecars outside the capsule.

**Tech Stack:** Python 3.11+, uv, hatchling, Pydantic 2, PyYAML 6, packaging 26, pytest, Ruff, mypy, OpenAI Python SDK 3.x (optional), POSIX descriptor APIs via the standard library and narrowly scoped `ctypes`, GitHub Actions on Ubuntu and macOS.

## Stable package APIs

Implementation may use private helpers, but these names and boundaries remain stable across the five slices:

```text
canonical_json(value) -> bytes
canonical_jsonl(values) -> bytes
sha256_bytes(value: bytes) -> str
stable_digest(domain: str, payload) -> str
stable_digest_bytes(domain: str, payload) -> bytes
canonical_timestamp(value: datetime) -> str

load_source_manifest_capture(path, *, input_root, invocation_cwd) -> CapturedSourceManifest
capture_inputs(captured_manifest, *, source_root, staging_root) -> CapturedInputs
materialize_case_index(captured_inputs, resolved_manifest) -> tuple[CaseIndexRowV1, ...]
materialize_plan(capsule_identity, resolved_manifest, case_index, captured_arms) -> tuple[PlanRowV1, ...]
prepare_capsule(request: PrepareRequest) -> PreparedCapsule
verify_capsule(path, *, mode) -> VerifyResultV1
resume_capsule(path, *, provider_factory) -> VerifyResultV1
finalize_capsule(path, *, seal_incomplete: bool = False) -> VerifyResultV1
```

`verify_capsule` parses future producer versions without requiring equality to the installed runner. Mutation paths separately enforce exact producer/runtime equality before reading credentials or constructing providers.
